### **2.3 Email, SMTP, and Mail Access Protocols**
  
  Email is one of the oldest and most fundamental internet applications, dating back to 1972. While it might seem less modern than other applications, it provides a classic and clear example of the client-server architecture.
#### **Three Major Components of Email**
  
  The email system is a distributed application built on three main components:
  
  1.  **User Agents (UAs)**
    *   **Definition:** The software used by a person to interact with the email system. Also known as a "mail reader" or "mail client."
    *   **Function:** Allows users to compose, edit, send, and read email messages.
    *   **Examples:** Microsoft Outlook, Apple Mail, the mail client on an iPhone.
    *   **Important Note:** Although you interact with messages on your user agent, the messages themselves (both incoming and outgoing) are stored on mail servers.
  
  2.  **Mail Servers**
    *   **Function:** The core infrastructure that stores and forwards emails. Mail servers are always on and always connected to the internet.
    *   Each user has a designated mail server where their account resides.
    *   A mail server contains two primary components for each user:
        *   **Mailbox:** Contains the incoming messages for a user.
        *   **Message Queue:** Contains the outgoing messages that the server is waiting to send to their destination.
  
  3.  **Simple Mail Transfer Protocol (SMTP)**
    *   **Definition:** The primary application-layer protocol for sending email messages between servers and from a user agent to a server.
    *   **Role:** SMTP is a **push protocol**. It is used to *push* messages from a client to a server, and from one server to another.
    *   **Client/Server Paradigm:** In the context of SMTP:
        *   The "client" is the entity sending the email (either the user agent or the sending mail server).
        *   The "server" is the entity receiving the email.
#### **Scenario: Alice Sends an Email to Bob**
  
  Let's trace the steps involved when a user, Alice, sends an email to another user, Bob.
  
  1.  **Compose:** Alice uses her **user agent** to compose an email message addressed to `bob@someschool.edu`.
  2.  **Send to Server:** When Alice clicks "Send," her user agent establishes an SMTP connection to her own mail server (e.g., `mail.alice.com`) and **pushes** the message to it. The message is then placed in the **message queue** on Alice's server.
  3.  **Server-to-Server Transfer (Initiation):** The client side of SMTP on Alice's server sees the message in its queue. It opens a TCP connection to Bob's mail server (`mail.bob.com`).
  4.  **Server-to-Server Transfer (Push):** Once the TCP connection is established, Alice's server, now acting as an SMTP client, **pushes** Alice's message to Bob's server over the connection.
  5.  **Store in Mailbox:** Bob's mail server receives the message and places it in **Bob's mailbox**.
  6.  **Retrieve:** At a later time, Bob uses his **user agent** to connect to his mail server and **pull** the new message from his mailbox to read it.
  
  **Key Insight:** Notice that SMTP is only used for *pushing* the email from the sender all the way to the receiver's mail server. The final step, where Bob retrieves the email from his server, uses a different type of protocol.
#### **The SMTP Protocol in Detail (RFC 5321)**
  
  *   **Transport Protocol:** SMTP runs on top of **TCP**, using it for reliable data transfer. It connects to the well-known **port 25** on the server.
  *   **Direct Transfer:** The sending server (acting as the client) establishes a direct TCP connection to the receiving server.
  *   **Three Phases of Transfer:**
    1.  **Handshaking:** A greeting phase where the client and server introduce themselves.
    2.  **Transfer of Messages:** The actual email message is sent.
    3.  **Closure:** The connection is terminated.
  *   **Command/Response Interaction:**
    *   Similar to HTTP, SMTP uses a human-readable, command/response model with ASCII text.
    *   **Commands:** Sent by the client (e.g., `MAIL FROM:`, `RCPT TO:`).
    *   **Responses:** Sent by the server, consisting of a status code and a human-readable phrase (e.g., `250 OK`).
#### **Comparison of SMTP and HTTP**
  
  *   **Push vs. Pull:**
    *   **HTTP:** Is primarily a **pull protocol**. The client pulls information from the server.
    *   **SMTP:** Is a **push protocol**. The client pushes information to the server.
  *   **Message Format:**
    *   Both use ASCII command/response interactions and status codes.
    *   **HTTP:** Each object is encapsulated in its own separate response message.
    *   **SMTP:** A single message can contain multiple objects (e.g., attachments) as a multi-part message.
#### **Mail Message Format (RFC 2822)**
  
  The format of the email message itself (what the user sees) is distinct from the SMTP protocol commands used to transfer it.
  
  *   **Structure:** An email message consists of:
    *   A **Header:** Contains lines like `To:`, `From:`, and `Subject:`. These are separate from the SMTP `MAIL FROM` and `RCPT TO` commands.
    *   A blank line.
    *   The **Body:** The main content of the message, which must be in 7-bit ASCII.
#### **Retrieving Email: Mail Access Protocols**
  
  SMTP only gets the message to the recipient's server. A different protocol is needed to get the message from the server to the recipient's user agent. These are **mail access protocols**, and they are **pull protocols**.
  
  *   **IMAP (Internet Mail Access Protocol):**
    *   The most widely used and modern access protocol.
    *   **Key Feature:** Messages are kept and managed on the server. The user agent can view and manipulate messages (e.g., create folders, delete messages) that remain stored on the server.
    *   This allows users to access their email from multiple devices and see a consistent state (e.g., a message read on a phone will also appear as read on a laptop).
  
  *   **POP (Post Office Protocol):** An older protocol where messages are typically downloaded from the server to the client and then deleted from the server.
  
  *   **HTTP:** Many modern webmail services (like Gmail, Outlook.com) use HTTP as their mail access protocol. The browser acts as the user agent, sending HTTP requests to the mail provider's web server, which in turn uses SMTP (to send) and IMAP/POP (to retrieve) on the user's behalf.
