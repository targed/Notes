## Time Delay Calculation
  
  In embedded systems, creating precise time delays is often crucial.  We can generate delays in software using loops and taking into account the execution time of AVR instructions.
  
  **Key Concepts:**
  
  *   **Machine Cycle (MC):** The basic unit of time for the CPU to execute an instruction.  For many AVR instructions, this is one or two clock cycles.
  *   **Clock Cycle (CC):** The period of the oscillator driving the AVR.  $T_{osc} = \frac{1}{f_{osc}}$, where $f_{osc}$ is the oscillator frequency.
  
  **Instruction Execution Time:**
  
  *   Most AVR instructions take 1 or 2 machine cycles.
  *   Some instructions (e.g., `JMP`, `CALL`) take more cycles.
  *   Branch instructions (e.g., `BRNE`, `BREQ`) can take 1 or 2 cycles, depending on whether the branch is taken or not. This is due to *branch penalty.*
  
  **Calculating Delay:**
  
  To calculate the delay generated by a piece of code:
  
  1.  **Determine the number of machine cycles** for each instruction.
  2.  **Sum the machine cycles** for all instructions in the loop or code segment.
  3.  **Multiply the total machine cycles** by the duration of one machine cycle (which is related to the clock cycle).
  
  **Example (Simple Delay):**
  
  Assume $f_{osc} = 1 \text{ MHz}$.  Therefore, $T_{osc} = \frac{1}{1 \text{ MHz}} = 1 \mu s$.  Also, 1 MC = 1 clock cycle (for simplicity, in this case).
  
  ```assembly
  LDI R16, 0xFF   ; 1 MC (1 μs)
  LOOP:
  DEC R16      ; 1 MC (1 μs)
  BRNE LOOP    ; 2 MCs if branch taken (2 μs), 1 MC if not taken (1 μs)
  NOP             ; 1 MC Waste time
  ```
  The instruction time is calculated by:
  
  $\text{Time (s)} = \text{Number of Machine Cycles} \cdot (\frac{\text{Clock Cycle}}{\text{Machine Cycle}}) \cdot (\frac{\text{Time}}{\text{Clock Cycle}}) = (\#MC) \cdot (\frac{CC}{MC}) \cdot (\frac{s}{CC}) $
  
  LDI: $ 1 MC (\frac{1 CC}{1 MC}) (\frac{1 \mu S}{1 CC}) = 1 \mu S $
  *   **Delay Calculation:**
  
  *   The loop executes 255 times (0xFF down to 0).
  *   Each iteration (except the last) takes 1 (DEC) + 2 (BRNE) = 3 MCs.
  *   The last iteration takes 1 (DEC) + 1 (BRNE, not taken) = 2 MCs.
  *   The `NOP` instruction takes 1 MC.
  *   So far:
    LDI R16, 0xFF => 1 machine cycle (1µs)
    DEC R16 => 1 machine cycle (1µs)
    BRNE LOOP => 2 machine cycles (2µs)
    NOP => 1 machine cycle (1µs)
  
  *   Total: $1 + (254 * 4) + 3 + 1= 1021$ MCs
  
  *   Total delay = 1021 MCs * 1 μs/MC =  1021 µs
  
  **Delay Subroutine:**
  
  It's common to create a subroutine for generating delays.
  
  ```assembly
  ; Delay subroutine (very simplified, not accurate)
  
  DELAY:
  LDI R20, 0xFF   ; Load a value into a counter register
  AGAIN:
  NOP           ; Waste some time
  NOP
  NOP
  DEC R20        ; Decrement the counter
  BRNE AGAIN     ; Branch back if not zero
  RET            ; Return from subroutine
  ```
  
  *Example Time Delay Calculation:*
  
  *Refer to the original handwritten notes showing the following code, and assume fosc=1MHz, to get a clock period of 1µs:*
  ```assembly
  .ORG 0
   LDI R16, HIGH(RAMEND) ;1
   OUT SPH, R16           ;1
   LDI R16, LOW(RAMEND)  ;1
   OUT SPL, R16           ;1

   LDI R16,0xAA          ;1
   OUT PORTB, R16        ;1
   RCALL Delay           ;3
   RJMP Back             ;2
  
  .ORG 0x300
  
  Delay: LDI R20, 0xFF      ;1
  AGAIN:
  NOP                 ;1
  NOP                 ;1
  NOP                 ;1
  DEC R20             ;1
  BRNE AGAIN          ;2/1
  RET                 ;4
  ```
  
  *   **`DELAY` Subroutine Calculation:**
    Inside the loop (AGAIN), there are 3 NOPs (1 cycle each), a DEC (1 cycle), and a BRNE (2 cycles if taken, 1 if not).  The loop runs 255 times.
    Total cycles inside loop (except last iteration) = (1 + 1 + 1+ 1+ 2) * 255 = 6 * 255 = 1530
    Last iteration BRNE:  1
    `RET` takes 4.
    `LDI R20, 0xFF` takes 1
    Total Delay Subroutine Cycles: 1 + 4 + 1530 + 1 = 1536 cycles.
    Delay = 1536 cycles \* 1µs/cycle = 1536 µs
  
  * **Main Loop:**
   *First pass:*
    The LDI and OUT take 1 µs each, before the first RCALL (3 µs)
    Total for first pass (pre-delay) = 4 \* 1µs + 2 * 3 µs = 10 µs.
     Add in the delay routine (1536 µs) + 4(post-delay) = 1550 µs.
      Total: 1550 µs
  
      *Every other pass*
       There is an additional RJMP (2µs) and LDI, OUT (1µs each).
         Add the values for the first pass, and we get:
          Total: 1553 µs
  
  **Nested Loops for Longer Delays:**
  
  For longer delays, you can nest loops.
  
  **Example (Nested Loops):**
  
  ```assembly
  ; Example: Loop 250,000 times
  ;Assume Fosc = 16 Mhz/20 Mhz
  
  ; 8 bits -> 0 - 255
  
  LDI R17,0x9F ; R17, output to porta
  com           ;
  LDI R20, 25
  Loop_3:
  LDI R21, 100
  Loop_2:
  LDI R22, 100
  Loop_1:
  com R17
  out PORTA, R17
  DEC R22        ; DEC (1)
  BRNE Loop_1    ; BRNE Loop_1; R22 = 0? (2)
  DEC R21        ; DEC (2)
  BRNE Loop_2    ; BRNE Loop-2; R21=0? (3)
  DEC R20        ; Dec (3)
  BRNE Loop_3    ; R20 = 0?
  ```
  
  *   We have three nested loops. R20 controls the outermost loop, R21 the middle loop, and R22 the innermost loop.
  *   The COM and OUT instructions will execute a total of 25*100*100 = 250,000 times.
  * Calculating the exact total delay requires careful consideration of each instruction's execution time and the number of times each loop iterates.
  
  **Using Timers for Delays:**
  
  For accurate and longer delays, using the AVR's built-in timers is *much* more efficient and precise than using software loops.  Timers will be covered in a later lecture.
