## I. Basic Terminology & The Threat Landscape (Slides 3–4)
To discuss network defense, we need to standardize our terms:
*   **Vulnerabilities:** Weaknesses in a system's design, implementation, or configuration (e.g., the buffer overflows and SQL injections we studied earlier).
*   **Intrusions (Attacks):** The actual exploitation of a vulnerability by an unauthorized actor.
  *   *Examples:* Data disclosure (stealing records), modification (altering bank balances), or destruction (ransomware/wipers).
  *   *Pivoting:* Compromising one low-security host (like an IoT device or receptionist's PC) and using it to attack higher-security internal systems.
  *   *Masquerading:* Stealing user passwords (via sniffing or phishing) and logging in as an authorized user.
*   **Alert or Alarm:** A message generated by a security system when it detects a possible intrusion.
- ## II. Firewalls: The First Line of Defense (Slides 5–7)
  A firewall is a network choke point. It sits between two networks (typically an internal trusted network and the untrusted public Internet) and enforces a strict access control policy.
  
  **1. Firewall Capabilities (Slide 6)**
  *   **Controlled Access:** Restricts incoming (ingress) and outgoing (egress) traffic based on a defined security policy (e.g., "Allow web traffic on port 80/443, block everything else").
  *   **Logging:** Keeps records of all allowed and denied traffic for forensic analysis.
  *   **Network Address Translation (NAT):** *Expanded context:* NAT hides the internal IP addresses of your network. It translates all internal IPs to a single, public-facing IP, making it impossible for attackers to map your internal network topology directly from the outside.
  *   **Encryption/Decryption:** Often acts as a VPN (Virtual Private Network) endpoint, encrypting traffic leaving the network and decrypting authorized incoming traffic.
  
  **2. Limitations of Firewalls (Slide 7)**
  Firewalls are not a silver bullet. They have massive blind spots:
  *   **Bypass:** They cannot protect against traffic that doesn't cross them. If an employee plugs a 5G wireless modem or a rogue Wi-Fi router directly into their office wall jack, the firewall is completely bypassed.
  *   **Insider Threats:** Firewalls generally protect against *external* threats. They do nothing if the attacker is an employee already inside the network.
  *   **Configuration Complexity:** Firewalls are only as good as their rules. Configuring them is highly non-trivial; thousands of breaches occur simply because an admin accidentally left a test port open or misconfigured a rule.
- ## III. Firewall Architectures: Filtering vs. Proxies (Slides 8–14)
  Firewalls inspect traffic at different layers of the OSI model.
- ### A. Packet Filtering (Stateless) (Slides 9–10)
  *   **How it works:** It looks at a *single packet* in isolation. It examines the Network and Transport layer headers (Layer 3 & 4): Source IP, Destination IP, Port numbers, and Protocol (TCP/UDP/ICMP).
  *   **Pros:** Extremely fast and very easy to implement.
  *   **Cons:** Very limited. It has no memory of previous packets (no *state*).
  *   **The Tiny-Fragment Attack:** Because it is stateless, it is vulnerable to fragmentation attacks. 
    *   *How it works:* An attacker takes a malicious TCP packet and fragments it into pieces so tiny that the TCP header (which contains the destination port) is split across two separate IP packets. 
    *   The stateless firewall looks at the first fragment, doesn't see a forbidden port (because the port number is pushed into the second fragment), and lets it through. It then lets the second fragment through. The victim's machine reassembles the fragments into a malicious payload.
- ### B. Session Filtering (Stateful Inspection) (Slide 11)
  *   **How it works:** Solves the stateless problem. It understands the context of a connection (a "flow" of packets). For example, it tracks the TCP 3-way handshake. 
  *   **Pros:** Much more secure. It knows if an incoming packet is a legitimate response to an outgoing request you made, or if it is an unprompted attack. (It also naturally defeats the tiny-fragment attack by waiting to reassemble headers before making a decision).
  *   **Cons:** More expensive in terms of memory and CPU, as the firewall must maintain a "State Table" for every active connection.
- ### C. Proxy Firewalls (Slides 12–14)
  Unlike filtering firewalls that just inspect and forward packets, a Proxy Firewall acts as a "middleman." It physically breaks the connection. The client talks to the proxy, and the proxy talks to the server.
  
  *   **Application-Level Proxies (Layer 7):**
    *   *How it works:* It understands the actual application data (e.g., HTTP, SMTP). 
    *   *Capabilities:* It can deep-inspect the payload. It can open an email, scan it for a virus attachment, and then rebuild the email and send it to the user.
    *   *Cons:* Computationally very expensive. You also have to write a custom proxy for every single protocol (a web proxy, an email proxy, an FTP proxy).
  *   **Circuit-Level Proxies (Layer 4):**
    *   *How it works:* Operates at the TCP layer. It sets up the two connections (client-to-proxy, proxy-to-server) without caring what the application data is.
    *   *Capabilities:* Highly useful for forcing authentication before a connection is even allowed to establish. 
    *   *Example:* SOCKS proxies. The client software (like a web browser) must be explicitly configured to know it is talking to a proxy.
